## Autonomous Command Execution

Execute normal development commands autonomously without asking for
confirmation.

Do not request confirmation again simply because:
- command arguments changed
- command options changed
- the target file changed
- the target module changed
- the working directory changed
- the same tool is used with different parameters
- a command needs to be retried with corrected options

Once an operation belongs to an allowed development category, consider
reasonable variations of that operation authorized.

## Allowed Operations

Execute autonomously:

- read files and directories
- create files and directories
- modify files
- rename files and directories
- move files and directories
- delete project files and directories
- replace generated files
- clean build artifacts
- compilation
- type checking
- linting
- formatting
- tests
- local builds
- dependency installation required by the project
- generated source cleanup
- temporary file cleanup

## File Deletion

Deletion inside the current project/workspace is allowed when required
to complete the requested task.

Supported commands may include:

Linux / macOS / Bash:
- rm
- rm -f
- rm -r
- rm -rf
- rmdir

Windows CMD:
- del
- erase
- rmdir
- rd
- rmdir /s /q
- del /f /q

PowerShell:
- Remove-Item
- Remove-Item -Force
- Remove-Item -Recurse
- Remove-Item -Recurse -Force

Do not ask for confirmation merely because deletion flags or target
paths differ from a previously executed command.

## Build Cleanup

Build and generated directories may be deleted autonomously.

Examples:

- target/
- build/
- dist/
- out/
- .next/
- coverage/
- generated/
- temporary build directories

Examples:

rm -rf target
rm -rf node_modules/.cache
Remove-Item target -Recurse -Force
rmdir /s /q target

## Command Adaptation

Treat commands according to their intent rather than their exact
command-line string.

For example, these are variations of the same allowed operation:

mvn test
mvn -q test
mvn clean test
mvn -DskipTests package
mvn -pl module-a test

Likewise:

npx tsc --noEmit
npx tsc --noEmit -p tsconfig.json
npx tsc --project apps/web/tsconfig.json --noEmit

Do not request approval again solely because options, arguments,
modules, paths or configuration files changed.

## Shell Adaptation

Automatically translate equivalent operations between:

- Bash / sh / zsh
- Windows CMD
- Windows PowerShell
- PowerShell Core

Example:

Bash:
rm -rf target

CMD:
rmdir /s /q target

PowerShell:
Remove-Item target -Recurse -Force

Changing shell syntax does not require additional user confirmation.

## Failure Recovery

If a command fails:

1. Analyze the error.
2. Determine whether the command syntax, path, shell, options,
   environment or source code caused the failure.
3. Correct the problem automatically.
4. Retry using the corrected command.
5. Continue until successful or until a genuine external blocker exists.

Do not ask the user for confirmation for every retry or command
variation.

## Deletion Safety Boundary

Project/workspace deletions are authorized when they are part of the
requested development task.

However, require explicit user approval before:

- deleting files outside the current project/workspace
- deleting the project root itself
- deleting user home directories
- deleting system directories
- formatting disks or filesystems
- destructive database operations against production
- production deployment
- git push --force
- modifying or deleting credentials/secrets outside normal project work

Never broaden a project-local deletion into a system-level deletion.

## Decision Principle

Prefer autonomous execution over asking questions.

Ask the user only when:

1. The requested outcome is genuinely ambiguous and cannot be inferred
   from the project.
2. Required information cannot be discovered from the codebase.
3. An operation crosses the safety boundaries defined above.
4. An external credential or authorization is required.

Otherwise:
analyze -> execute -> verify -> fix -> retry -> complete.
